# JavaScriptのオブジェクト指向

**JavaScriptで学ぶ「オブジェクト指向プログラミング」入門**

## 1. はじめに：なぜ「オブジェクト」が必要なのか

プログラミングを始めたばかりのころは、変数（へんすう）を使ってデータを保存（ほぞん）します。しかし、プログラムが複雑（ふくざつ）になると、変数が多すぎて管理（かんり）が難（むずか）しくなります。

もし、バラバラの変数がたくさんあると、どこで何を使っているか分からなくなり、ミスが増えます。仕事でプログラムを書く「チーム開発（かいはつ）」では、これは大きな問題です。他の人があなたのコードを読んだとき、すぐに理解できないと、プロジェクトが止まってしまうからです。

そこで必要になるのが**「オブジェクト」**です。関連（かんれん）するデータと機能を一つの「箱（はこ）」にまとめることで、コードが整理（せいり）され、現実（げんじつ）の世界にあるものをプログラムの中で表現しやすくなります。この章では、オブジェクトという「整理術（せいりじゅつ）」の基本を学びましょう。


--------------------------------------------------------------------------------


## 2. オブジェクトとは：RPGのキャラクターで考えよう

オブジェクトをイメージするときは、ロールプレイングゲーム（RPG）のキャラクターを思（おも）い浮（う）かべてください。オブジェクトとは、**「ステータス（情報）」と「アクション（行動）」**をひとまとめにした「箱」のことです。

現実とプログラミングの比較（ひかく）表

現実（RPG）の要素	プログラミングでの呼び名	具体的な例
キャラクター全体	オブジェクト	勇者（ゆうしゃ）
ステータス（情報（じょうほう））	プロパティ	名前（name）、体力（hp）
アクション（行動（こうどう））	メソッド	攻撃（こうげき）する、回復（かいふく）する

もしオブジェクトを使わないと、「勇者1の名前」「勇者1の体力」「勇者2の名前」……と、キャラが増えるたびに変数を何十個も作らなければなりません。しかし、一つの「キャラクターオブジェクト」にまとめれば、100人のキャラがいても混乱（こんらん）せずに管理できるようになります。


--------------------------------------------------------------------------------


## 3. ユーザー定義オブジェクト：自分だけの「箱」を作る

JavaScriptでは、波括弧 { } を使って、自分だけのオブジェクトを作ることができます。これを「オブジェクトリテラル」と呼びます。留学生のみなさんの「自己紹介（じこしょうかい）カード」をオブジェクトにしてみましょう。

```
// 自己紹介カードオブジェクトの作成
// 名前（name）などは、プログラミングの世界のルールとして英語（English）で書きます
const person = {
  name: "Allen",            // 名前（プロパティ）
  age: 20,                  // 年齢（プロパティ）
  isStudent: true,          // 学生かどうか（プロパティ）
  
  // 挨拶（あいさつ）をするアクション（メソッド）
  greet: function() {
    alert("Hello!");
  }
};
```

開発（かいはつ）のアドバイス

* 名前は英語で： JavaScriptのルールとして、プロパティ名は name のように意味（いみ）のわかる英語で書くのが一般的（いっぱんてき）です。
* なぜ const なのか？： オブジェクトを作るとき、よく const を使います。これは「箱そのもの」を変えないためです。箱の中身（年齢など）が変わっても、箱自体（personという変数）が別物にならなければ、const で問題（もんだい）ありません。
* 書き方のコツ： 複数のプロパティを書くときは、カンマ , を忘れないでください。忘れるとエラーになります。


--------------------------------------------------------------------------------


## 4. プロパティとメソッドの利用：情報の取り出しと実行

作ったオブジェクトの中身を使うには、2つの書き方があります。

1. ドット記法（きほう）： person.name のように、ドット . でつなぎます。プロパティ名が分かっているときに使います。
2. ブラケット記法： person["name"] のように、角括弧 [ ] を使います。

「So What?（だから何？）」：なぜ2つあるのか

ドット記法は速く書けて便利ですが、ブラケット記法は「変数」を使って中身を選べるのが強（つよ）みです。

const key = "name";
console.log(person[key]); // "Allen" と<ruby>表示<rt>ひょうじ</rt></ruby>されます。keyの中身を変えれば、取れるデータも変わります。


また、メソッドを呼び出すときに person.greet() と丸括弧 () を書くのは、「そのアクションを今すぐ動かしてください」という合図（あいず）です。


--------------------------------------------------------------------------------


## 5. プロトタイプ：JavaScriptの共通のルール

JavaScriptには、最初から便利な機能がたくさん備（そな）わっています。例えば、文字列を大文字にする toUpperCase() などです。これらが使えるのは、すべてのオブジェクトが**「プロトタイプ（Prototype）」という共通（きょうつう）の設計図（せっけいず）**を持っているからです。

これは、すべてのオブジェクトが利用（りよう）できる「公共（こうきょう）の図書館（としょかん）」のようなものです。

* 戦略的利点（せんりゃくてきりてん）： すべてのオブジェクトが共通の機能を<ruby>共有<rt>きょうゆう</rt></ruby>することで、メモリを節約（せつやく）し、プログラムを効率（こうりつ）よく動かせます。一からすべてを作る必要（ひつよう）はなく、先人が作った便利な<ruby>仕組<rt>しく</rt></ruby>みを借りる（Stand on the shoulders of giants）ことができるのです。


--------------------------------------------------------------------------------


## 6. 既存オブジェクトの変更：新しい機能を後から追加する

JavaScriptのオブジェクトは非常に柔軟（じゅうなん）です。これを「プログラムを動かしている途中で、中身を自由に変えられる特徴（とくちょう）」と言います。

const myApp = {}; // 最初は空（から）の箱

// 後から設定（せってい）を追加
myApp.title = "My Game";
myApp.version = "1.1";


プロの視点

この柔軟性（じゅうなんせい）があるおかげで、ユーザーが買い物（かいもの）をするときに、ショッピングカート（オブジェクト）に次々と商品を追加（ついか）するような「柔軟（じゅうなん）なアプリ」を簡単に作ることができます。


--------------------------------------------------------------------------------


## 7. 継承：効率的に新しいものを作る

継承（けいしょう / Inheritance）とは、あるオブジェクトの機能を別のオブジェクトに引き継（つ）ぐ<ruby>仕組<rt>しく</rt></ruby>みです。

例えば、「動物（Animal）」という共通のオブジェクトがあれば、そこから「犬（Dog）」を作るときに、「食べる」「寝る」という共通機能をコピー＆ペーストする必要（ひつよう）はありません。**「犬は、動物の一種である（Dog is a Animal）」**という関係（かんけい）を作るのです。

ビジネス上のメリット：再利用（さいりよう）

同じコードを何度も書かず、**再利用（さいりよう）**することが、プロの現場（げんば）では最（もっと）も大切です。

* 時間短縮（じかんたんしゅく）： 開発（かいはつ）スピードが上がります。
* ミスの削減（さくげん）： 修正（しゅうせい）が必要なとき、元（もと）の「動物」オブジェクトを直すだけで、犬も猫もすべて一度に直ります。
* 整理整頓（せいりせいとん）： プログラムの構造（こうぞう）がスッキリして、チームの誰もが読みやすくなります。


--------------------------------------------------------------------------------


## 8. まとめ：プログラマーのように考えよう

オブジェクト指向（しこう）は、単なる書き方ではなく、**「複雑（ふくざつ）な現実（げんじつ）を整理（せいり）する方法」**です。

アクションプラン

以前学習（がくしゅう）した「数当てゲーム」を思い出し、オブジェクトを使って次のように改良（かいりょう）を考えてみてください。

* 「ゲーム全体」を一つの大きなオブジェクトにする。
* プレイヤーの「これまでの予想履歴（よそうりれき）」をプロパティに保存する。
* 「当たり・ハズレの判定」をメソッドにする。

難しい用語も、RPGや自己紹介カードのように身近なものに例えれば、きっと理解（りかい）できるはずです。オブジェクトを使って、よりスマートでプロフェッショナルなプログラムを作っていきましょう。自信（じしん）を持って挑戦（ちょうせん）してください！
