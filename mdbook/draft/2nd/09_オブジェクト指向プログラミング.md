# JavaScriptのオブジェクト指向

**JavaScriptで学ぶ「オブジェクト指向プログラミング」<ruby>入門<rt>にゅうもん</rt></ruby>**

## 1. はじめに：なぜ「オブジェクト」が必要なのか

プログラミングを始めたばかりのころは、<ruby>変数<rt>へんすう</rt></ruby>を使ってデータを保存（ほぞん）します。しかし、プログラムが複雑（ふくざつ）になると、<ruby>変数<rt>へんすう</rt></ruby>が多すぎて管理（かんり）が難（むずか）しくなります。

もし、バラバラの<ruby>変数<rt>へんすう</rt></ruby>がたくさんあると、どこで何を使っているか分からなくなり、ミスが増えます。仕事でプログラムを書く「チーム<ruby>開発<rt>かいはつ</rt></ruby>」では、これは大きな問題です。他の人があなたのコードを読んだとき、すぐに理解できないと、プロジェクトが止まってしまうからです。

そこで必要になるのが**「オブジェクト」**です。関連（かんれん）するデータと機能を一つの「箱（はこ）」にまとめることで、コードが整理（せいり）され、現実（げんじつ）の世界にあるものをプログラムの中で表現しやすくなります。この章では、オブジェクトという「整理術（せいりじゅつ）」の基本を学びましょう。


--------------------------------------------------------------------------------


## 2. オブジェクトとは：RPGのキャラクターで考えよう

オブジェクトをイメージするときは、ロールプレイングゲーム（RPG）のキャラクターを思（おも）い浮（う）かべてください。オブジェクトとは、**「ステータス（情報）」と「アクション（行動）」**をひとまとめにした「箱」のことです。

現実とプログラミングの比較（ひかく）表

現実（RPG）の要素	プログラミングでの<ruby>呼<rt>よ</rt></ruby>び<ruby>名<rt>な</rt></ruby>	具体的な<ruby>例<rt>れい</rt></ruby>
キャラクター全体	オブジェクト	<ruby>勇者<rt>ゆうしゃ</rt></ruby>（ゆうしゃ）
ステータス（情報（じょうほう））	プロパティ	名前（name）、体力（hp）
アクション（行動（こうどう））	メソッド	攻撃（こうげき）する、回復（かいふく）する

もしオブジェクトを使わないと、「<ruby>勇者<rt>ゆうしゃ</rt></ruby>1の名前」「<ruby>勇者<rt>ゆうしゃ</rt></ruby>1の体力」「<ruby>勇者<rt>ゆうしゃ</rt></ruby>2の名前」……と、キャラが増えるたびに<ruby>変数<rt>へんすう</rt></ruby>を何十個も作らなければなりません。しかし、一つの「キャラクターオブジェクト」にまとめれば、100人のキャラがいても混乱（こんらん）せずに管理できるようになります。

## 3. ユーザー<ruby>定義<rt>ていぎ</rt></ruby>オブジェクト：自分だけの「箱」を作る

JavaScriptでは、波括弧 { } を使って、自分だけのオブジェクトを作ることができます。これを「オブジェクトリテラル」と呼びます。留学生のみなさんの「<ruby>自己<rt>じこ</rt></ruby>紹介（じこしょうかい）カード」をオブジェクトにしてみましょう。

```
// <ruby>自己<rt>じこ</rt></ruby>紹介カードオブジェクトの作成
// 名前（name）などは、プログラミングの世界のルールとして英語（English）で書きます
const person = {
  name: "Allen",            // 名前（プロパティ）
  age: 20,                  // 年齢（プロパティ）
  isStudent: true,          // 学生かどうか（プロパティ）
  
  // 挨拶（あいさつ）をするアクション（メソッド）
  greet: function() {
    alert("Hello!");
  }
};
```

<ruby>開発<rt>かいはつ</rt></ruby>のアドバイス

* 名前は英語で： JavaScriptのルールとして、プロパティ名は name のように意味（いみ）のわかる英語で書くのが一般的（いっぱんてき）です。
* なぜ const なのか？： オブジェクトを作るとき、よく const を使います。これは「箱そのもの」を変えないためです。箱の中身（年齢など）が変わっても、箱自体（personという<ruby>変数<rt>へんすう</rt></ruby>）が別物にならなければ、const で問題（もんだい）ありません。
* <ruby>書<rt>か</rt></ruby>き<ruby>方<rt>かた</rt></ruby>のコツ： 複数のプロパティを書くときは、カンマ , を忘れないでください。忘れるとエラーになります。

## 4. プロパティとメソッドの利用：情報の取り出しと実行

作ったオブジェクトの中身を使うには、2つの<ruby>書<rt>か</rt></ruby>き<ruby>方<rt>かた</rt></ruby>があります。

1. ドット記法（きほう）： person.name のように、ドット . でつなぎます。プロパティ名が分かっているときに使います。
2. ブラケット記法： person["name"] のように、角括弧 [ ] を使います。

「So What?（だから何？）」：なぜ2つあるのか

ドット記法は速く書けて便利ですが、ブラケット記法は「<ruby>変数<rt>へんすう</rt></ruby>」を使って中身を選べるのが強（つよ）みです。

const key = "name";
console.log(person[key]); // "Allen" と<ruby>表示<rt>ひょうじ</rt></ruby>されます。keyの中身を変えれば、取れるデータも変わります。


また、メソッドを呼び出すときに person.greet() と丸括弧 () を書くのは、「そのアクションを今すぐ動かしてください」という合図（あいず）です。

## 5. プロトタイプ：JavaScriptの共通のルール

JavaScriptには、最初から便利な機能がたくさん備（そな）わっています。<ruby>例<rt>たと</rt></ruby>えば、文字列を大文字にする toUpperCase() などです。これらが使えるのは、すべてのオブジェクトが**「プロトタイプ（Prototype）」という共通（きょうつう）の設計図（せっけいず）**を持っているからです。

これは、すべてのオブジェクトが利用（りよう）できる「公共（こうきょう）の図書館（としょかん）」のようなものです。

* <ruby>戦略<rt>せんりゃく</rt></ruby>的利点（せんりゃくてきりてん）： すべてのオブジェクトが共通の機能を<ruby>共有<rt>きょうゆう</rt></ruby>することで、メモリを節約（せつやく）し、プログラムを<ruby>効率<rt>こうりつ</rt></ruby>（こうりつ）よく動かせます。一からすべてを作る必要（ひつよう）はなく、先人が作った便利な<ruby>仕組<rt>しく</rt></ruby>みを借りる（Stand on the shoulders of giants）ことができるのです。

## 6. 既存オブジェクトの変更：新しい機能を後から追加する

JavaScriptのオブジェクトは非常に柔軟（じゅうなん）です。これを「プログラムを動かしている途中で、中身を自由に変えられる特徴（とくちょう）」と言います。

const myApp = {}; // 最初は空（から）の箱

// 後から<ruby>設定<rt>せってい</rt></ruby>を追加
myApp.title = "My Game";
myApp.version = "1.1";


プロの視点

この柔軟性（じゅうなんせい）があるおかげで、ユーザーが買い物（かいもの）をするときに、ショッピングカート（オブジェクト）に次々と商品を追加（ついか）するような「柔軟（じゅうなん）なアプリ」を簡単に作ることができます。

## 7. 継承：<ruby>効率<rt>こうりつ</rt></ruby>的に新しいものを作る

継承（けいしょう / Inheritance）とは、あるオブジェクトの機能を別のオブジェクトに引き継（つ）ぐ<ruby>仕組<rt>しく</rt></ruby>みです。

<ruby>例<rt>たと</rt></ruby>えば、「動物（Animal）」という共通のオブジェクトがあれば、そこから「犬（Dog）」を作るときに、「食べる」「寝る」という共通機能をコピー＆ペーストする必要（ひつよう）はありません。**「犬は、動物の一種である（Dog is a Animal）」**という関係（かんけい）を作るのです。

ビジネス上のメリット：再利用（さいりよう）

同じコードを何度も書かず、**再利用（さいりよう）**することが、プロの現場（げんば）では最（もっと）も大切です。

* 時間短縮（じかんたんしゅく）： <ruby>開発<rt>かいはつ</rt></ruby>スピードが上がります。
* ミスの削減（さくげん）： 修正（しゅうせい）が必要なとき、元（もと）の「動物」オブジェクトを直すだけで、犬も猫もすべて一度に直ります。
* 整理<ruby>整頓<rt>せいとん</rt></ruby>（せいりせいとん）： プログラムの構造（こうぞう）がスッキリして、チームの誰もが読みやすくなります。
