# オブジェクトを改造する

既存のオブジェクトを自分好みに作り変えることを、プログラミングの世界では **「拡張（かくちょう / Extension）」** や **「カスタマイズ」** と呼びます。

これは **「買ってきた自転車（じてんしゃ）に、ライトをつけたり色をぬったりして改造（かいぞう）すること」** に例えることができます。

## I. オブジェクトを改造する

### 1. 既存のオブジェクトを改造する2つの方法

JavaScriptでは、すでに動いているオブジェクトに後から「新しいパーツ」を追加したり、「古いパーツ」を新しいものに取り替えたりできます。

#### a) **追加する**

特定の1人（1つのインスタンス）だけに、新しいプロパティやメソッドを追加します。

* **イメージ：** 自分の自転車だけに、特別なステッカーを貼る。
* **書き方：** `オブジェクト名.新しい名前 = 値;`

```javascript
const myCar = { brand: "Toyota" };

// 後からプロパティを追加
myCar.color = "Red";

// 後からメソッドを追加
myCar.horn = function() {
  console.log("プップー！");
};

myCar.horn(); // 実行できる！

```

#### b) **オーバーライド（上書き）する**

親から受け継いだ機能を、自分流のやり方に書き換えます。

* **イメージ：** お父さんから譲り受けたカメラだけど、レンズを最新のものに交換して使いやすくする。
* **書き方：** 同じ名前で新しく定義し直す。

```javascript
class Robot {
  greet() {
    console.log("ハロー、ロボットデス。");
  }
}

class JapaneseRobot extends Robot {
  // 親の greet を上書き（オーバーライド）
  greet() {
    console.log("こんにちは、ロボットです。");
  }
}

const robo = new JapaneseRobot();
robo.greet(); // 「こんにちは...」が出る

```



### 2. 留学生への例え話：スマホのケースとアプリ

> 「JavaScriptのオブジェクトは、一度作ったら終わりじゃないんだ。
> 1. **直接追加：** スマホに『お気に入りのストラップ』をつけるようなもの。そのスマホだけの特別。
> 2. **プロトタイプ追加：** OSをアップデートして『全員のスマホに新しい計算機アプリ』を入れるようなもの。
> 3. **オーバーライド：** 決まった『着信音（ちゃくしんおん）』を、自分の好きな音楽に変えるようなものだよ。
> 
> 
> こうやって、元の形を壊さずに自分らしく使いやすくするのが、JavaScriptの面白いところなんだ！」



### まとめテーブル

| 改造（かいぞう）の名前 | どうなる？ | 誰に影響（えいきょう）する？ |
| --- | --- | --- |
| **プロパティ追加** | 新しいデータを足す | そのオブジェクトだけ |
| **メソッド追加** | 新しい動きを足す | そのオブジェクト（または全員） |
| **オーバーライド** | 古い動きを新しい動きに変える | その子クラスから生まれた人全員 |


### 📝 留学生へのアドバイス

> 「改造はとても便利だけど、やりすぎると『元の形がどうだったか』が分からなくなって、他の人が困ることがあるんだ。
> 特に **`Array.prototype`** などを改造するときは、**『みんなの共有スペースに勝手に私物を置かない』** というマナーがあることも、一緒に覚えておこうね！」



いかがでしょうか？「後から自由に変えられる」というJavaScriptの柔軟（じゅうなん）な性格が伝わればバッチリです。

## II. プロトタイプとプロトタイプチェーン

JavaScriptの「プロトタイプ（Prototype）」と「プロトタイプチェーン」は、多くの学習者がつまずく難しい山場です。

留学生の方には、これを**「家系図（かけいず）」**や**「秘伝のレシピの受け継ぎ」**に例えて説明してあげると、イメージがしやすくなります。

---

### 1. プロトタイプ（Prototype）とは？

一言でいうと、**「共通の予備（よび）パーツ」**です。

JavaScriptでは、すべてのオブジェクトが「親（プロトタイプ）」を持っています。もし自分の中に必要な道具（メソッドやプロパティ）がなくても、**「親の持っている道具を借りて使う」**ことができる仕組みです。

---

### 2. プロトタイプチェーン（Prototype Chain）とは？

「自分になければ親、親になければそのまた親…」と、**さかのぼって探しに行く「鎖（くさり）」のようなつながり** のことです。

#### **身近な例え：秘伝のカレーレシピ**

1. **あなた（インスタンス）：** カレーを作ろうとします。
2. **自分のキッチン：** レシピがありません。
3. **お父さんの家（プロトタイプ）：** 「カレーのレシピある？」と聞きます。
4. **おじいさんの家（親のプロトタイプ）：** お父さんも持っていなければ、さらにおじいさんに聞きに行きます。
5. **ルーツ：** 誰かがレシピを持っていれば、あなたはそれを使ってカレーが作れます。

---

### 3. なぜこの仕組みがあるの？

もし100人の学生オブジェクトを作るとき、全員に「自己紹介メソッド」を持たせると、メモリー（コンピューターの脳）をたくさん使ってしまいます。

* **プロトタイプを使わない：** 全員が自分の辞書（じしょ）を持っている（重い！）
* **プロトタイプを使う：** 教室に1冊だけ辞書を置き、全員でそれを共有する（軽い！）

---

### 4. コードで見る「探しに行く流れ」

```javascript
const animal = {
  eats: true
};

const dog = {
  barks: true
};

// dog の親（プロトタイプ）を animal に設定
Object.setPrototypeOf(dog, animal);

console.log(dog.barks); // true (自分の中にある)
console.log(dog.eats);  // true (自分にはないが、親にあるので借りてきた！)
console.log(dog.fly);   // undefined (家系図を最後まで探したけど、どこにもない)

```



### 5. 留学生へのアドバイス：`__proto__` と `prototype`

ここが一番混乱するポイントなので、こう教えてあげてください。

> 「**`prototype`** は、**『子供たちに貸してあげる道具箱』**のこと。
> `__proto__` は、**『自分の親の道具箱をのぞく窓』**のことだよ。
> 名前は似ているけど、**『貸す側』**か**『借りる側』**かの違いなんだ。まずはこれだけ覚えておけば大丈夫！」


### まとめテーブル

| 用語 | やさしい日本語 | 英語のイメージ |
| --- | --- | --- |
| **Prototype** | 共通の道具箱 / 秘伝のレシピ | Blueprint / Shared assets |
| **Prototype Chain** | 先祖（せんぞ）をたどる鎖 | Search link / DNA |
| **Inheritance** | 継承（親の機能を使えること） | Inheritance |

---

「自分にないものは、先祖から借りればいい」。この考え方がJavaScriptの根本（こんぽん）にあります。



#### **② プロトタイプを使って「全員」に追加する**

そのプロトタイプから生まれた「全員」に、新しい機能を持たせます。

* **イメージ：** マンションの住人全員が使える「共有のラウンジ」に、新しいテレビを置く。
* **書き方：** `クラス名.prototype.メソッド名 = function() { ... };`

```javascript
// 全ての配列（Array）に「2倍にする」という新しい機能を追加してみる
Array.prototype.double = function() {
  return this.map(n => n * 2);
};

const numbers = [1, 2, 3];
console.log(numbers.double()); // [2, 4, 6]

```

> **注意：** `Array` や `Object` などの標準（ひょうじゅん）の道具を勝手に改造するのは、他のプログラムとぶつかる可能性があるので、プロの世界では慎重（しんちょう）に行います。
