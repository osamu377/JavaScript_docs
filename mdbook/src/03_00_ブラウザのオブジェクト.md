# ブラウザのオブジェクト

**初心者のためのJavaScript：ブラウザを動かす「オブジェクト」の仕組み**

みなさん、こんにちは！IT専門学校（せんもんがっこう）でプログラミングを教えているシニア講師（こうし）です。留学生（りゅうがくせい）のみなさんも、これからJavaScriptを使ってウェブサイトに「動き」をつける方法を楽しく学んでいきましょう。

プログラミングは難（むずか）しく見えますが、実は **「ブラウザという家（いえ）」の中にある「道具（どうぐ）」の使い方**を覚（おぼ）えるだけなんです。今日は、その道具である「オブジェクト」について、プロの視点（してん）からやさしく解説（かいせつ）します。

## 3. JavaScriptは「誰が」「何をするか」を指示するマニュアル

JavaScriptとは、Webページを表示しているブラウザに『これこれこういうことをしなさい』と命令するための **マニュアル** のようなものです。たとえば飲食店でアルバイトをする場合、わかりやすく書かれたマニュアルがあれば、ミスをすることなく作業することができます。

さまざまな人が集まって会社ができているのと同じように、Webページももさまざまな部品から構成されています。そして、「会社に何かをしてもらう」というのは、実際には「その会社の人に何かをしてもらう」ことです。同じように、「Webページを動かす」というのは「Webページを作っている部品たちに何かをしてもらう」ということです。

JavaScripはマニュアルですから、「みんなで協力して、これをやりなさい」とぼんやりした命令をするのではなく、「Aさんはこれをして」「Bさんはあれをして」と一人ひとりの作業を正確に、細かく書く必要があります。

この「Aさん」「Bさん」のことをJavaScriptでは **『オブジェクト』** と呼んでいます。ちょっと難（むずか）しそうな言葉に聞こえるかもしれませんが、中身は難（むずか）しくありません。今は、「Webページの中には、たくさんの **『オブジェクト』** と呼ばれるものがいて、JavaScriptを使って、彼らに命令すれば、仕事をしてくれるらしい」くらいに思ってもらえばいいのです。


### 1. BOM/DOMツリーは「ブラウザが作った地図」

われわれが「こうしなさい」と指示する相手は、オブジェクトと呼ばれる、Webページのいろいろな部品です。その部品とは、たとえば、ひとまとまりの文である『段落』であり、『見出し』であり、あなたが文字を入力する『テキストボックス』であり、あなたがクリックする『ボタン』です。

ブラウザは、HTMLファイルを受け取ると、中身を読み取って、その指示に従って **オブジェクト** たちを作り、それらをコンピュータが扱いやすい **「木（Tree）」** の形に並べ替えます。これを **DOM（Document Object Model）ツリー** と呼びます。

またブラウザ自身も自分の持っている機能をツリーの形で整理しています。これを **BOM（Browser Object Model）** と呼びます。 

### 2. ツリーの「家族（かぞく）」関係

DOMツリーの中では、それぞれの要素（Element）を **「ノード（Node）」** と呼び、家族のような名前で関係を表します。

* **Document（ルート）：** 木の「一番下の根っこ」または「一番上の先祖」。すべての始まりです。
* **Parent（親）：** ある要素を包んでいる外側のタグ。
* **Child（子）：** タグの中に入っている内側のタグ。
* **Sibling（兄弟）：** 同じ親の中に並んでいるタグ同士。

### 3. JavaScriptの仕事：地図をたどって操作する

JavaScriptはこの「地図」を使って、オブジェクトの場所を探し出し、命令（めいれい）を出します。

1. **見つける（Select）**
「IDが 'btn' のボタン（子）を探して！」
2. **変える（Change）**
「そのボタンの色を赤くして！」
3. **作る・消す（Create / Delete）**
「新しいリストを1つ増やして、古いのは消して！」

### 4. 留学生へのアドバイス：なぜ「ツリー」と呼ぶの？

> 「HTMLのコードはただのテキストだけど、ブラウザの中では **『生きている木』** のように枝分かれしているんだ。
> 枝（えだ）の先にある葉っぱ（文字や画像）を動かしたいときは、幹（みき）から順番にたどっていくイメージを持つと、プログラミングがすごく分かりやすくなるよ！」

### まとめテーブル

| 言葉 | 意味 | 役割 |
| --- | --- | --- |
| **Document** | 木の全体 | JavaScriptが操作する入り口 |
| **Node（ノード）** | 木の節（ふし） | タグやテキストの一つひとつ |
| **Element（要素）** | タグそのもの | 具体的なパーツ（`<div>`, `<h1>`など） |

## 1. はじめに：ブラウザオブジェクトとは何か

JavaScriptを学ぶとき、一番（いちばん）大切（たいせつ）な考え方が「オブジェクト」です。

ブラウザを **「一つの大きな家」** だと想像（そうぞう）してみてください。家の中には、テレビ、エアコン、冷蔵庫（れいぞうこ）などの「家具（かぐ）」や「道具」がありますよね？ JavaScriptでは、これらの道具を「オブジェクト」と呼びます。

なぜこれを学ぶのか（So What?） オブジェクトを理解（りかい）すると、ウェブページの文字を書き換えたり、ボタンを押（お）したときに色（いろ）を変えたり、ページを自由自在（じゅうじざい）に構築（こうちく：組み立てること）できるようになります。

まずは、この家の「家主（やぬし）」であり、すべてを管理（かんり）している「Windowオブジェクト」から見ていきましょう。


--------------------------------------------------------------------------------


## 2. すべての基点：Windowオブジェクト

ブラウザのタブを開（ひら）いたとき、その画面全体（がめんぜんたい）を管理しているのがWindow（ウィンドウ）オブジェクトです。これはJavaScriptの世界（せかい）の「王様（おうさま）」です。

* 階層（かいそう：重なりの順番）のイメージ： Windowオブジェクトはすべての「ルート（根っこ）」です。Windowという大きな箱（はこ）の中に、この後説明するDocument（書類）やLocation（場所）など、すべての道具が入っています。
* 王様のインパクト： もし王様（Window）がいなくなると、その国（タブ）にあるすべてのデータや書類（Document）も消えてしまいます。タブを閉じるとページの情報が消えるのはそのためです。
* Windowの便利な機能（きのう）： alert() や prompt() などがあります。
  * alert("こんにちは！")：画面にメッセージを出す「拡声器（かくせいき：大きな声を出す機械）」のようなものです。
  * prompt("お名前は？")：ユーザーに文字を入力してもらう「アンケート用紙」のような役割（やくわり）です。

次は、王様が持っている大切な「書類」、つまりページの中身を指す「Document」についてお話しします。

## 3. ウェブページを操る：DOMとDocumentオブジェクト

ウェブページに表示（ひょうじ）されている文字や画像（がぞう）そのものを操作（そうさ）するのがDocument（ドキュメント）オブジェクトです。

ここで大切なのが **DOM（Document Object Model）です。HTMLの構造（こうぞう）は、枝分かれした「木（ツリー）」** のような親子関係（おやこかんけい）になっています。これを「DOMツリー」と呼びます。

* Documentの役割： Documentは、ページ全体への「入り口」です。特定の場所を探（さが）し出すときは、今のプログラミングで最もよく使われる次の方法（セレクタ）を使いましょう。
  * document.querySelector('#id名') この命令（めいれい）を使えば、木の中から狙（ねら）った部品（ぶひん）を正確（せいかく）に見つけることができます。

ターゲットが見つかったら、次は具体的にその「部品」をどう動かすかを見ていきましょう。


--------------------------------------------------------------------------------


## 4. ページ上の「部品」：Elementオブジェクト

HTMLのタグ（見出し、段落（だんらく）、ボタンなど）のひとつひとつをElement（エレメント）オブジェクトと呼びます。

RPGのキャラクターに例（たと）えるとわかりやすいです。

* プロパティ（ステータス）： 名前、HP（体力）
* メソッド（行動）： 攻撃（こうげき）する、回復（かいふく）する

JavaScriptでも同じです。

* 中身を書き換える： .textContent を使うと、見出しの文字などを安全に書き換えることができます。
* 情報の変更： .setAttribute() を使うと、画像のファイル名を変えたり、リンク先を新しくしたりできます。

これにより、ユーザーの操作（そうさ）に合わせてリアルタイムに画面を更新（こうしん）できるようになります。


--------------------------------------------------------------------------------


## 5. デザインを動的に変える：Styleオブジェクト

CSSの知識（ちしき）とJavaScriptを組み合わせると、ページの見た目を自由に変えられます。それがStyle（スタイル）オブジェクトです。

JavaScriptからCSSを変えるときは、プロが必ず守るルールがあります。

* キャメルケースのルール： CSSで「-（ハイフン）」を使うプロパティ（例：background-color）は、JavaScriptではハイフンを消して、次の文字を大文字にします（例：backgroundColor）。
* 視覚的フィードバック： マウスを乗せたときに背景色を変えるなど、ユーザーに「今ここを触（さわ）っているよ！」と伝えることで、使いやすいページになります。


--------------------------------------------------------------------------------


## 6. ユーザーの動きを捕まえる：Eventオブジェクト

ユーザーが「クリックした」などの出来事（できごと）をイベントと呼びます。これを捕（つか）まえるのが「イベントリスナー（見張り番）」です。

イベントが発生した瞬間に、詳しい情報を運（はこ）んでくるのがEvent（イベント）オブジェクトです。

* 見張り番と報告書（ほうこくしょ）： 「イベントリスナー」が見張りを行い、何か起きたら「Eventオブジェクト」という名前の報告書を書き上げます。
* So What?： 報告書には「どのボタンが押されたか」「マウスの場所はどこか」が書かれています。これを使うことで、双方向（そうほうこう：やり取りができる）のウェブ体験（たいけん）が作れるのです。


--------------------------------------------------------------------------------


## 7. 入力を受け取る：Formオブジェクト

ユーザーが入力した名前などを扱うのがForm（フォーム）オブジェクトです。

* 値（value）の取り出し： 入力された文字は .value というプロパティに入っています。
* アプリの信頼性（しんらいせい）： 例えば、送信ボタンを一度押（お）したら、.disabled = true という命令（めいれい）でボタンを「無効（むこう）」にしましょう。これで、二回連続（れんぞく）で送ってしまうミスを防（ふせ）ぎ、アプリの信頼性を高めることができます。


--------------------------------------------------------------------------------


## 8. URLと移動の管理：Locationオブジェクト

ブラウザのアドレスバーにあるURL（住所）を管理するのがLocation（ロケーション）オブジェクトです。

* 戦略的（せんりゃくてき）なインパクト： 今のURLを調べるだけでなく、新しいページにジャンプさせたり（遷移：せんい）、ページをリロード（再読み込み）させたりできます。ログインが終わった後に別のページへ移動（いどう）させるときなどに使います。


--------------------------------------------------------------------------------


## 9. 便利な特殊機能：タイマー、クッキー、その他のオブジェクト

ウェブページを便利にするための特別なオブジェクトも紹介（しょうかい）します。

* タイマー（Timer）： setInterval を使うと、1秒ごとに時計を動かすなど、**自動化（じどうか）**のメリットが得（え）られます。
* クッキー（Cookie）： ブラウザに情報を保存（ほぞん）します。次にサイトに来たときに「おかえりなさい！」と表示（ひょうじ）するなど、ユーザーを大切にする演出（えんしゅつ）が可能です。
* その他： Navigator（ブラウザの情報）や History（戻るボタンの記録）などがあります。

## 10. 【補足】歴史的な書き方：with文について

古いプログラムを見ていると with という言葉が出てくるかもしれません。

これは「オブジェクトの名前を省略（しょうりゃく）して短く書く」ための古い道具でした。しかし、今のプロフェッショナルの世界では**「非推奨（ひすいしょう：使ってはいけない）」**とされています。

理由は、コードがどこを指しているのか分かりにくくなり、エラーの原因（げんいん）になるからです。同じように、昔の変数宣言（へんすうせんげん）である var も避け、現代的な let や const を使いましょう。
