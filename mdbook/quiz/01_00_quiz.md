JavaScriptを始める前に：学習定着度確認テスト

1. はじめに：本テストの目的と構成

Web開発の世界へようこそ！これからプログラミング言語であるJavaScript（ジャバスクリプト）の学習を始めますが、その前にとても大切なことがあります。それは、Webが動く「仕組み」の全体像を理解することです。

どんなに難しいコードを書けても、その命令が「どこで」「誰に対して」送られるのかを知らなければ、実際に動くプログラムを作ることはできません。このテストは、皆さんがWeb開発の基礎体力を備えているかを確認するためのものです。単なる言葉の暗記ではなく、実務でプログラムが動かない原因（デバッグ / Debugging）を見つけるための基礎知識を評価します。

本テストは以下の3つのセクションで構成されています。

1. WWWとインターネットの仕組み： プログラムが動く「舞台」を理解します。
2. Webページを作る3つの技術： HTML・CSS・JavaScriptの「役割分担」を整理します。
3. JavaScriptの基本概念： プログラムの核心である「イベント」と「オブジェクト」を学びます。

これらのセクションはすべて、皆さんが将来「自分の思い通りにWebページを動かす」ための論理的なステップとなっています。それでは、まずは私たちのプログラムが活躍する舞台、インターネットの仕組みから見ていきましょう。

2. セクションI：WWWとインターネットの仕組み（問1～問7）

インターネットを理解することは、Webサイトの「住所（URL）」と、データの受け渡しである「リクエスト（Request / 注文）」と「レスポンス（Response / 返事）」の流れを把握することです。このシステム全体の流れを知ることは、エラー解決（デバッグ）において非常に戦略的な意義を持ちます。どこで問題が起きているのかを論理的に絞り込めるようになるからです。

【問題】

問1：WWW（ワールド・ワイド・ウェブ）の仕組みを説明するものとして、最も適切な例えはどれですか？

1. 情報を運ぶための「高速道路」
2. 世界中のコンピュータが網のようにつながり、情報を共有する「図書館」
3. 電子メールを送るための「専用ポスト」
4. データを保存するためだけの「巨大な倉庫」

問2：Webブラウザ（ChromeやSafariなど）の役割を「図書館」に例えると何にあたりますか？

1. 本を管理している「図書館のスタッフ」
2. 本に書かれている「文章」
3. 本を借りに来た「お客さん（クライアント / Client）」
4. 本が置いてある「本棚」

問3：Webサーバ（Server）の役割を「図書館」に例えたとき、正しい説明はどれですか？

1. 24時間動いており、データを保管して送り返す「本を管理している人」
2. ユーザーが手元で操作する「マウスやキーボード」
3. Webページのデザインを「きれいにするペンキ」
4. サイトの「名前（ドメイン）」を決めるルール

問4：ウェブサイトが表示されるまでの「4つのステップ」において、正しい順番はどれですか？

1. レンダリング → レスポンス → DNS → リクエスト
2. リクエスト → レスポンス → DNS → レンダリング
3. DNS → リクエスト → レスポンス → レンダリング
4. リクエスト → DNS → レスポンス → レンダリング ※注：DNS（住所の確認）、レンダリング（Rendering / 組み立て）

問5：URL（住所）について正しく説明しているものはどれですか？

1. ブラウザがデザインを組み立てるためのマニュアル
2. 特定のサイトがどこにあるかを教える、世界に一つしかない「整理番号」
3. HTMLのデータを暗号化するための秘密の鍵
4. サーバーの電源を遠隔でオンにするためのスイッチ

問6（So What? - デバッグの視点）：ブラウザに正しいURLを入力したのに「ページが見つかりません」と出ました。もし「DNS（住所の確認）」のステップに問題がある場合、どのような状況だと考えられますか？

1. サーバーは動いているが、送られてきたデータが壊れている
2. サイトの名前（ドメイン）から、正しい数字の住所（IPアドレス）が特定できていない
3. サーバーが忙しくて、返事を返すのが遅れている
4. 自分のパソコンの画面を組み立てる機能（レンダリング）が壊れている

問7（So What? - デバッグの視点）：サーバーから「レスポンス（返事）」が全く返ってこない場合、ユーザーの画面はどうなりますか？

1. ページのデザインだけが崩れて表示される
2. サーバーからデータが届かないため、画面に何も表示されないかエラーになる
3. ブラウザが勝手に想像して、以前のデータを表示する
4. 文字だけが表示され、画像が消える

Webサイトが表示されるまでの流れを理解できたら、次はWebページを構成する具体的な技術について確認しましょう。

3. セクションII：HTML・CSS・JavaScriptの役割分担（問8～問12）

Webページは、3つの技術がチームとして働くことで完成します。これらを「家づくり」に例えて理解することが重要です。各技術は独立しているのではなく、統合されて一つのユーザー体験（UX）を生み出します。

【問題】

問8：HTMLの役割を「家づくり」に例えると何にあたりますか？

1. 壁紙やインテリアなどの「見た目」
2. 柱（はしら）、壁（かべ）、床（ゆか）などの「骨組み・構造」
3. 電気が通って動く「自動ドアや照明」
4. 家を建てるための「土地の住所」

問9：CSSの役割を正しく説明しているものはどれですか？

1. 文章に「意味」を持たせる
2. ボタンをクリックしたときの「計算」を行う
3. ペンキの色やインテリアなど、ページの「見た目・デザイン」を整える
4. サーバーにデータを保存する

問10：JavaScriptの役割を「家づくり」の比喩（ひゆ）で説明すると、どのような状態を指しますか？

1. 家の周りに庭を作る
2. 家の設計図（図面）を書く
3. 「電気」を通して、機械装置（自動ドアやエレベーター）を動かせるようにする
4. 家の屋根に看板（名前）を付ける

問11：JavaScriptが全く使われていないWebページは、ユーザーにどのような体験を与えますか？

1. 文字が全く表示されず、真っ白な画面になる
2. 動きや反応がない、静止した「紙のポスター」のような状態になる
3. デザインが非常に美しく、写真が勝手に動き出す
4. インターネットに接続しなくても、すべての機能が使えるようになる

問12：JavaScriptの最大の特徴は、ユーザーと何ができるようになることですか？

1. 一方的な情報の放送
2. ユーザーの操作に反応を返す「対話（コミュニケーション）」
3. Webページの物理的な印刷
4. サーバーの電源を直接切ること

JavaScriptは、いわば「家」に命を吹き込む「電気」です。では、その電気を使って、どうやって「スイッチ」や「センサー」を制御するのか、その仕組みを見ていきましょう。

4. セクションIII：JavaScriptの基本概念：イベントとオブジェクト（問13～問20）

JavaScriptでプログラムを書くことは、コンピュータに対して「誰が」「何をする」という明確なマニュアル（命令）を与えることです。コンピュータは曖昧（あいまい）な指示を理解できません。このセクションでは、動作の「きっかけ」と「対象」の定義について学びます。

【問題】

問13：JavaScriptにおける「イベント（Event）」の定義として、最も適切なものはどれですか？

1. サーバーの中に新しいデータを保存すること
2. ユーザーが操作したことで起きる「出来事（合図）」
3. HTMLのタグを新しく書き換えること
4. プログラムの文法間違い（エラー）のこと

問14：次のうち、JavaScriptの「イベント」に該当しないものはどれですか？

1. ボタンをクリック（Click）する
2. キーボードで文字を入力する
3. 画面を上下に動かす（スクロール / Scroll）
4. パソコン本体の色を青色に塗り替える

問15：JavaScriptが命令を出す対象となる、Webページの部品（ボタンや画像など）のことを何と呼びますか？

1. イベント (Event)
2. センサー (Sensor)
3. オブジェクト (Object)
4. プロトコル (Protocol)

問16：JavaScriptの命令（マニュアル）を作る際に、不可欠な3つの要素は何ですか？

1. 「いつ」「どこで」「誰と」
2. 「何が起きたら（イベント）」「誰が（オブジェクト）」「何をする（動作）」
3. 「HTML」「CSS」「JavaScript」
4. 「名前」「メールアドレス」「パスワード」

問17（状況設定型）：自動ドアが動く仕組みをJavaScriptの用語で説明する場合、正しい組み合わせはどれですか？

1. 人が前に来た ＝ オブジェクト、ドアが開く ＝ イベント
2. 人が前に来た ＝ イベント、ドアが開く ＝ 何をする（動作）
3. 人が前に来た ＝ URL、ドアが開く ＝ レンダリング
4. 人が前に来た ＝ CSS、ドアが開く ＝ HTML

問18：JavaScriptで操作する「オブジェクト」は、いつ、誰が作るものですか？

1. Webブラウザが、HTMLとCSSという設計図をもとに作り上げる
2. サーバーが、プログラムを動かす前にあらかじめ作成して送る
3. ユーザーが、キーボードで一から作成する
4. インターネットの回線が自動的に作り出す

問19（状況設定型）：JavaScriptの命令（マニュアル）を「会社での仕事」に例えると、どのようなものですか？

1. 「みんなで適当に協力して頑張ってください」という曖昧な指示
2. 「Aさん（特定のオブジェクト）はこの仕事をして」と、個別の担当者に伝える正確な指示
3. 社長が社員の顔を覚えるためのメモ
4. 会社を建てるための土地の権利書

問20：なぜJavaScriptで命令を書くときに「誰が（どのオブジェクトが）」をはっきりさせる必要があるのですか？

1. サーバーの場所を世界中から探すため
2. コンピュータが迷わずに、特定の部品（ボタンなど）を操作できるようにするため
3. Webページの文字数を増やして、検索されやすくするため
4. URLの入力ミスを自動で直すため

以上の20問でテストは終了です。お疲れ様でした！最後に解答を確認して、学習のポイントを振り返りましょう。

学習アドバイス

テストの結果はいかがでしたか？

もし間違えてしまった問題があっても、がっかりする必要はありません。大切なのは、JavaScriptを単なる呪文の暗記として捉えるのではなく、**「Webページという『家』に『電気（JS）』を通して、ユーザーの『合図（イベント）』に合わせて特定の『部品（オブジェクト）』を動かす」**というイメージを持つことです。

また、エラーが起きたときには「リクエストは届いたかな？」「レスポンスは返ってきたかな？」と考える癖をつけてください。これが「デバッグ（エラー解決）」の第一歩です。

次のステップでは、JavaScriptが操作する対象となる「家」そのもの、つまりHTMLとCSSについて詳しく学んでいきます。この土台を理解することで、JavaScriptを使って「どのボタン（オブジェクト）を動かすか」を正確に選べるようになります。自信を持って次のステップへ進みましょう！
