このテキストの目的は、みなさんにオブジェクトというキャラクターを操る方法を知ってもらい、その面白さを感じてもらうことです。
と言うと、当然、「オブジェクトって、何？」という疑問がわきますね？　それについては、このあとすぐ！
でも、その前に。










さて、仕事でExcelを使っているとき、同じ作業を繰り返しやらなければいけなくなって、うんざりすることがありませんか？　単にうんざりするだけならまだしも、長時間の作業で効率が落ちてしまったり、あるいは、うっかりミスをやってしまいそうになってヒヤッとしたり、さまざまな問題が起きることもあるでしょう。それを防ぐ方法はないのでしょうか？
そもそも、世界最初のコンピュータといわれるENIACは、人間が同じ作業（弾道計算）を繰り返し行うのを肩代わりし、かつ、人間よりも素早く正確に実行するために作られたものです。また、コンピュータが普及しはじめた初期の段階において、多くの官庁や企業がコンピュータを導入したのは、徴税業務など、『一定のルールにしたがった計算を多くの人数分繰り返すこと』が必要な仕事あり、その計算処理を人に代わって実行させるためでした。
Excelのようないわゆる『表計算ソフト』は、パソコンが普及し始めた当初から存在し（というより、逆に『表計算ソフトがあったからこそ、ビジネス用パソコンは普及した』といっても過言ではないのですが）、それを使ってきた人たちは、「表計算ソフトもコンピュータ上で動いている以上、ソフト自身に面倒な繰り返し作業を肩代わりさせて、私たちの『うんざり』を減らす方法があるんじゃないか？」と考えていました。あらかじめ作業の手順書を作っておいて、『はい、このとおりにやりなさい』と表計算ソフトに命令したいわけです。
 
※	世界最初のパーソナル・コンピュータ用表計算ソフト　VisiCalcの画面。まだVBAのような機能はなかったが、このソフトの登場でPCがビジネスの世界に広がった。

そのためには、手順書を理解し、それに従って動く機能を、ソフトに組み込むことが必要です。そして実際、パソコンの性能が上がるにつれて、多くの表計算ソフトに、そうした機能（「マクロ機能」と呼ばれました）は搭載され、各社はその強力さを競うようになったのです。最初に業界をリードしたのはLotus 1-2-3というソフトでした。それを追うMicrosoft Excelは、当初、グラフィカルで分かりやすい操作方法だけが売りでした。しかし、やがて1-2-3と同等かそれ以上のマクロ機能を搭載し、最終的に表計算ソフトのチャンピョンとして、生き残ることになりました。

Excel VBAとは、Excelに『これこれこういうことをしなさい』と命令するための、作業手順書です。人間が何かをする場合も、ルールにのっとって書かれた手順書があれば、おおむね間違いなく、効率的に作業することができます。ましてコンピュータなら、正確な作業手順書さえあれば、何度でも、ひとつの間違いもなく、しかも高速に作業を行ってくれます。コンピュータ上で動くExcelも同じです。
その作業手順書であるExcel VBAには、20年を超える長い歴史があり（VBAという形なる以前まで含めれば、もっとあります）、その機能は驚くほど発展しています。その気になれば、Windows OSを操作することもできるほどです。そのせいで、この手順書の書き方は、学べば学ぶほど、奥の深いものになりました。したがって、それを学ぶため入口もたくさんあります。
そのたくさんの入り口の中で、このテキストでは、みなさんに、まずオブジェクトというキャラクターを操る方法から伝えてゆこうと思います。
これを学んでもらえれば、あとは「オブジェクトに何ができるのか？」「それ以外にExcel VBAにあらかじめ用意されている機能はどんなものなのか？」など、自分であれこれ調べながら、自分の業務に役立ててゆくことができます。ブロックの組み立て方を覚えれば、あとは必要なパーツを入手するだけで、自分の作りたいものを作ることができるでしょう。VBAの場合、このパーツとはExcel VBAの「オブジェクトやその他の部品の機能」に当たります。そして、それらについては、Webにも、市販本にも、たくさんの情報があります。ですから、まずはブロックを組み立てる面白さを覚えてほしいのです。

さきほど、Excel VBAは高度に発展した、と述べました。しかし、だからといって、入口まで狭き門になったわけではありません。もともとプログラマでない人が使ってきたExcel VBAです。いまでも高度な知識なしに書き、動かすことができます。
　まずは、この入門編でオブジェクトを操る面白さを感じ取ってください。

Ⅰ.どんな相手に命令するか
1.	オブジェクト
イントロダクションで、VBAでは「Excelに『これこれこういうことをしなさい』と命令する」と書きました。しかし、これをさらに具体的に言うと、実はExcel全体への命令というより
Excelを形作っているいろいろな部品に指示・命令する
ということになります。
人間の組織がさまざまな人から構成されているのと同じように、Excelもさまざまな『もの』から構成されています。そして、「組織に何かをさせる」というのは、実際には「その組織に属する人間に何をさせる」ことであるように、「Excelに作業させる」というのは「Excelを構成する『もの』たちに作業させる」ということです。VBAとは作業手順書ですから、「みんなで協力して、これをやりなさい」とぼんやりした依頼をするのではなく、「Aさんにはこれをさせて、Bさんにはあれをさせて」と一人ひとりの作業レベルまで、細かく砕いて書く必要があります。
この『もの』のことをVBAでは『オブジェクト』と呼んでいます。言葉の響きはちょっと難しそうかもしれませんが、中身は難しくありません。「Excelの中には、たくさんの『オブジェクト』と呼ばれるキャラクターがいて、その連中に言えば、何か仕事をしてくれるらしい」くらいに思ってもらえばいいのです。










というわけで、われわれが「こうしなさい」と指示する相手は、オブジェクトと呼ばれる、Excelのいろいろな部品です。その部品とは、たとえば、あなたが値や計算式を入力するセルであり、そのセルを載せたシートであり、そして、そのシートを編集するためにあなたが開いたブックです。Excel VBAとは、そうしたExcelが持つオブジェクトを操作して、さまざまな処理をさせるためのツールなのです。

2.	セルというオブジェクト
もう少し、「オブジェクト」について、詳しく説明してみましょう。そして、そのために、ここではスターウォーズ・エピソード４『新たなる希望』冒頭のR2-D2にたとえてみます。

【SW EP4 冒頭のストーリー】
レイア姫は、同盟のスパイが入手した『デス・スター』（帝国の巨大要塞）の設計図をロボットR2-D2に記憶させ、同盟軍の秘密基地へ向かっている。
が、その宇宙船をダース・ベーダー率いる帝国軍が急襲する
レイア姫は助けを求めるホログラム(動画)をR2-D2に託し、タトウゥーン星のオビワン・ケノビに見せるように命令する。
命令を受けて、R2-D2はC-3POとともに宇宙船を脱出し、タトウゥーンへ向かうのだが・・・。

さて、ここでR2-D2は＜デス・スターの設計図＞と＜レイア姫のホログラム＞という二つのデータを持っています。つまり、それらを入れるための入れ物が彼の中にあったということです。
そして同時に、＜タトウィーン星のオビワン・ケノビのところへ行く＞、＜ホログラムを再生する＞という二つの機能も持っていることになります。ロボットですから、元から持っている機能以外の命令を与えられても、実行することはできません。「ボッチェ語の通訳をしなさい」とR2-D2に言ったら、彼はその機能を搭載したC3P-Oを呼んでくるでしょう。自分ではできないからです。












さて、R2-D2と同じように、Excelのセルというオブジェクトも、データを入れる入れ物と特定の命令を実行する機能を持っています。
たとえばセルに入力された値を保持する入れ物があり、「自分（セル）の背景色はこの色」というように、色のデータを保持する入れ物があります。また入力された値や数式をすべてクリアする、自分をどこか別の場所にコピーするなど、いろいろな命令を実行する機能も、あらかじめ持っています。



 





オブジェクトの持っている＜データ＞あるいは＜データを入れる入れ物＞をプロパティと言います。
またオブジェクトの持っている＜命令を実行する機能＞をメソッドと言います。
つまり『オブジェクトを操る』とは、そのオブジェクトが持っているプロパティを変更したり、メソッドを呼び出したりして、さまざまな処理を行うことを言うのです。

2.	手順書をどこに書くか？＝標準モジュール
VBAプログラムを書く道具である、VBEを起動するところまで出来ました。でも、まだVBAプログラムを書く場所がわかりません。
実は、プログラムを書くことができる場所はたくさんあります。しかし、特別な理由がなければ、「標準モジュール」に書くのが普通です。それはまさにVBAプログラムを書くためにある専用のエリアなので、いろいろ使い勝手がよいのです。
標準モジュールは、ワークシートのように各ブックに所属します。ですが、新しいブックを作った段階では、まだ存在しません。新しいシートを挿入するように、新しい標準モジュールを挿入する必要があります。この操作はVBE上で行います。

標準モジュールを挿入する
1.	VBEのメニューバーの[挿入]をクリックし、表示されるメニューから[標準モジュール]をクリックする。
 
2.	「Module1」が表示されることを確認する
 
 
※ すでにModule1が存在すれば、自動的にModule2となります

標準モジュールが画面に表示されました。いよいよこの上に、VBAプログラムを書いてゆきます。まずは、「Subプロシージャ」という入れ物から。

3.	手順をまとめる入れ物＝Subプロシージャ
VBAプログラムを書くには、最初にまず、「Sub プロシージャ」という入れ物を作ります。
Subプロシージャとは「ここからここまでが一連の作業です」ということを示すひとつのくくり・まとまりのようなものです。肩ひじ張った言い方では、「VBAプログラムの最小実行単位」となります。でも、これでは何のことかわかりませんね。なので、スポーツに例えましょう。
野球の選手に「ボールを投げなさい」と指示します。そうすると、選手はボールを利き手に握り、腕をいったん後ろに回して、ふたたび前に振り出し、適当なところで握っていたボールを放す、という一連の手順を実行します。一連の手順が「ボールを投げなさい」という一つの命令にまとめられているわけです。

 　© freedesignfile.com

Subプロシージャも同様です。たとえば、”HaisouryoKeisan”というSubプロシージャに商品の配送料金を計算するための一連の手順を書いたとします。そうしておくことで、ユーザーは「HaisouryoKeisanを実行しなさい」とExcelに伝えるだけで、配送料を計算させることができます。そんなふうに一連の手順をまとめるための入れ物が、Subプロシージャなのです。
では、Subプロシージャを書いてみましょう！
標準モジュールに、次のように入力してください。あ、でも、書き終わっても、まだEnterキーはたたかないで！
 
MyFirstSubの後ろでカーソルが点滅していますね？　さあEnterキーをたたいてみましょう。
 
1回キーをたたいただけなのに、たくさんの文字が挿入されました。それに”sub”と小文字で書いたのに、自動的に”Sub”と頭が大文字になりました。
VBEには、スマホの予測変換のように、必要な文字を予測しながら、自動的に書き込んでくれる、便利な機能があります。すでに書き込んだ文字も、必要に応じて変更してくれます。そのせいで、最小限のキー入力でプログラムを書くことができるのです。

ところで、今、あなたが標準モジュールに書き込んだ（そしてVBEか補足してくれた）文には、どんな意味があるのでしょうか？
まず、”Sub”は「ここから先はSubプロシージャの記述ですよ」という宣言です。必ず、”End Sub”というキーワードと一緒に使います。”Sub”と”End Sub”に挟まれたエリアが、ひとつのSub プロシージャであることを示します。
次の”MyFirstSub”がSubプロシージャの名前です。Excelから呼び出すときは、この名前で呼び出します（呼び出し方は後ほど）。うしろに空っぽのカッコ”()”がくっついていますが、これについては、ここでは説明しません。今はまだ、「Subプロシージャって名前の後ろに”()”が付くんだ」と単純に覚えておいてください。それで十分です。

さて、入れ物ができましたが、まだ中身がありません。この入れ物に中身を入れましょう。
下のように” Range(“A1”).Value = 1000”と入力してください。これはあるオブジェクトへの指示です。入れ物の部分と中身の部分をパっと見で区別できるように、行の頭でTABキーを打って、中身を入れ物よりTABひとつ分、右になるようにして、書きはじめましょう。

Sub MyFirstSub()
Range(“A1”).Value = 1000
End Sub

あれ？　でも、書いている途中で、下に何か出てきましたね。
 
Excelで作業をしているとき、これによく似たものが出てきませんでしたか？　たとえばセルに数式を入れるとき…
 
そう、こんなやつです。VBEもセルと同じように、自動的に「こんなふうに書きなさい」と書式を教えてくれるのです。でも、残念ながら英語表記...。

気を取り直して、続きを書いてみましょう。
今度は、“Range(“A1”).”とドットまで書いたところで、ドロップダウンリストが出てきました。
 
これはセルが持っているプロパティやメソッドのリストです(※)。 のマークがメソッドで、 のマークがプロパティです。

※	本当は、Rangeオブジェクトのプロパティやメソッドです。Rangeとはセル範囲を示すもので、単一のセルを指す場合もありますが、本来の意味は、複数のセルを含む一定の領域を示すものです。ただ、しばらくの間、説明を簡単にするために、複数のセルの場合を無視します。Range=セルと思って、説明を読んでください。

このリストからマウスで”Value”プロパティを選ぶこともできます。でも今は（キーボードから手を放してマウスに持ち替えるのも面倒ですから）、そのままキー入力を続けましょう。
“V”と打つと、表示が少し変わりました。
 
　“V”で始まるプロパティにリスト表示が飛びました。続けて打ちます。
　“Valu”まで入力すると、リスト上のValueが青くハイライトされましたね。
 
ここでTABキーを押すと、”Value”と確定されます。もちろん、最後の”e”を自分で打ってもかまいません。
Valueというプロパティ名まで書けたら、残りを入力してしまいましょう。
 

書き終えましたか？　素晴らしい。では、プログラムを実行する前に、あなたが書いた『中身』の意味を、簡単に説明します。
”Range(“A1”)はA1セルを指します。”Value”はセルに入っている値を示すプロパティ名です。A1セルの値プロパティを示す場合は、
Range(“A1”).Value
というふうに、オブジェクト名とプロパティ名を”.”でつなぎます。
そして、”=”は代入演算子とよばれるものです。ここでは”1000”をA1セルの値プロパティに代入しています（『代入』という数学用語にアレルギーをお持ちの方は、「”1000”をA1セルの値プロパティに入れています」と読み替えてください）。詳しくは、後ほど説明しますが、今は「プロパティに何かを入れるときは、”=”という記号を使うんだ」くらいに思っていてください。
というわけで、この一文は「A1セルさん、君の値プロパティに1000を入れるから、そのまま持っていてね」というオブジェクトへの作業指示になるのです。

1.	セルのプロパティを操作する
　セルの指定方法について、あらためて述べます。
Excelには、たくさんのオブジェクトがあります。したがって、ただ、「これをこうしてください」ではなく、「XXさん、これをこうしてください」というふうに、作業すべき人が「XXさん」であることを、はっきりと示さなければなりません。VBA上でオブジェクトを特定するには、以下のような書式を使います。
オブジェクトの種類(“名前”)
【例】
A1セル　→　Range(“A1”)
Sheet1シート　→　WorkSheets(“Sheet1”)

　また、それぞれのオブジェクトには複数のプロパティがあるので、操作対象のプロパティを、
オブジェクトの種類(“名前”).プロパティ名
というふうに記述して、指定します。
【例】
A1セルの値プロパティ　→　Range(“A1”).Value
Sheet1シートの名前プロパティ　→　WorkSheets(“Sheet1”).Name

【例題】
A2セルに数値909を入れるプログラムを、Example01という名前で書きさい
【解答】
Sub Example01()
	Range(“A2”).Value = 909
End Sub

前章の復習ですから、簡単ですね？
とりあえず、この通りに書いて、実行してみてください。方法は、前節で説明した二つのうちの、どちらを使ってもかまいません。

次は数値ではなく、文字列を入れるプログラムです。
文字が二つ以上並んだものを、プログラミングの世界では「文字列」といいます。というか、実は文字が一つだけのものも、別にするのがめんどくさいので（？）、「文字列」として扱うことがほとんどです。
「文字列」という言葉は、Excelの書式でも使いますね。あれと同じです。数値であれば、足し算・引き算などの数値計算ができますが、文字列ではできません。文字列は、原則、人に読ませるためのものです。
下の例題はセルに文字列を入れる例です。ここでは”ロースかつ丼”という文字列を”(ダブル・クォート)で囲んでいることに注意してください。そうしないとエラーになります。

【例題】
A1セルに、”ロースかつ丼”という文字列を入れるプログラムを、Example02という名前で書きなさい
【解答】
Sub Example02()
	Range(“A1”).Value = “ロースかつ丼”
End Sub

これも、この通りに書いて、実行してみてください。「1000」となっていたセルA1が”ロースかつ丼”に変わるはずです。

・	R[-2]は、「アクティブなセルから見て２つ前の行」の意味。つまり6行の２つ前だから、4行目。 
・	Cは「同じ列」という意味。つまりB列。
というわけで、B4のセルを指すわけです。
※	余談ですが、FormulaR1C1でなく、Formulaというプロパティもあって、こちらには、”=B4*B5”が入ります。
 
ちなみに、もし、D7であれば、R[1]C[2]になります。
とすると、R[-1]Cの意味は分かりますね。一つ前の行の同列、つまりB5セルです。
で、その２つのセル（B4とB5）の掛け算を行う、というのが、上の数式の意味です。

【例題6】
次の順番で動くSubプロシージャをExercise07という名前で書きなさい。書き終わったら、ステップ実行して、動きを確認しなさい。
①	C1セルに文字列”赤いよ”を入れる
②	C1セルの文字を赤色にする

　まあ、さっきの練習問題とよく似てるので、大丈夫かな。あれ、でも、「ただし、セルの文字色を操作する方法については、下記を参照」がないぞ。
　そうです。自分で調べてください。
　…といったらグーグル先生に聞いちゃいますか？　もちろん、それも１つの方法です。でも、思い出してください。「マクロの記録」機能を使えば
Excel上で自分がやった操作をVBAとして記録してくれるんですよね？　ということは、たとえば「セルの文字色を赤にする」とう操作を記録すれば、それがすなわち、「セルの文字色を赤にする」VBAプログラムなんです。つまり、いちいちグーグル先生に聞かなくても、簡単に分かってしまうんです。
　というわけで、実際にやってみましょう。
 
　上の図のように、A1の文字を赤くしました。このとき記録されたマクロは、こうなります。 
　ふむ、見たことがない書き方ですね。
　“With”というキーワードは記述をまとめるのに使います。上の”With”と”End With”に挟まれた行にあるものは、本当は”With”のあとの”Selection.Font”に続くものです。
つまり、Withを使ってまとめる前は、
Selection.Font.Color = -16776961
Selection.Font.TintAndShade = 0
だったのを、「”Selection.Font”までは同じだから、まとめちゃえ」とやった結果が、Withを使った、上の記述になるわけです。
　といっても、ルールはあります。「どうせなら”Selection.Font.”と最後にドットまでつけてまとめてしまえ」と思っても、エラーになります。ルール（VBAというプログラム言語のルールですから、「文法」と言います）で、そう決まっているからです。これについては理由を調べるより、「そういうものだ」と覚えてしまったほうが速いでしょう。
　いずれにしても、これで文字を赤くするには、二つのプロパティを設定すればよいらしいことが分かりました。
　では書いてみましょう。

Sub Example06()
	Range(“C1”).Value = “赤いよ”
	Range(“C1”).Font.Color = -16776961
	Range(“C1”).Font.TintAndShade = 0
	Range(“D1”).Value = “青いよ”
	Range(“D1”).Font.Color = -4165632
	Range(“D1”).Font.TintAndShade = 0
End Sub

　または”With”を使って書くこともできます。

Sub Example06()
	Range(“C1”).Value = “赤いよ”
	With Range(“C1”).Font
		.Color = -16776961
		.TintAndShade = 0
	Range(“D1”).Value = “青いよ”
	With Range(“D1”).Font
.Color = -4165632
		.TintAndShade = 0
	End With
End Sub

本当のことを言うと、”.TintAndShade = 0”は、なくてもかまいません。これは色の明暗を「-1」から「1」までの数値で指定するプロパティで、0はその中間ですから、いわばディフォルトで、通常はもともとこの値になっています。こんなふうに、余計な文まで記述されてしまうのも、マクロの記録の欠点と言われています。
無駄なところを省くと、こんなプログラムになります。

Sub Example06()
	Range(“C1”).Value = “赤いよ”
	Range(“C1”).Font.Color = -16776961
	Range(“D1”).Value = “青いよ”
	Range(“D1”).Font.Color = -4165632
End Sub

少し説明がめんどくさくなったかもしれません。とりあえずは、上記のようなダイエットは後回しでいいと思います。プログラムは動いてナンボですので、余計な部分があってもちゃんと動くものが、余計な部分を削ろうとして動かなくなったプログラムより、よっぽどましなのです。
では、最後にもう1つだけ練習問題をやって、このパートを終わりにしましょう。
