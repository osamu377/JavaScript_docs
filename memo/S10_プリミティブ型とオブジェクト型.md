# プリミティブ型とオブジェクト型

```JavaScript
let theDay = new Date(2030, 5, 1);
let msg = "Hello";
```

`Date`オブジェクトに`new`が必要な理由と、文字列（String）に`new`が不要な理由の背後には、JavaScriptが持つ「**プリミティブ型**」と「**オブジェクト型**」の明確な違いがあります。

-----

## 🧐 プリミティブ型とオブジェクト型

JavaScriptのデータには、大きく分けて「プリミティブ型（基本型）」と「オブジェクト型（参照型）」の2種類があり、この違いが生成方法に影響しています。

### 1\. プリミティブ型（例: 文字列 / String）

文字列（String）、数値（Number）、真偽値（Boolean）などはプリミティブ型に分類されます。

| 項目 | 文字列 (`'hello'`) |
| :--- | :--- |
| **データ** | **単純な値**（それ自体がデータ） |
| **メモリ** | メモリ上の**決まった場所**に、値が直接格納される。 |
| **生成方法** | **代入（リテラル）** でシンプルに生成。 |

#### `new`が不要な理由

文字列は「`hello`」という単純な値だけで完結しており、特別な初期化処理や、複雑な内部状態を持つ必要がないため、最もシンプルな代入構文で生成されます。

```javascript
// シンプルな値なので、newは不要
let str = 'apple';
```

#### なぜメソッドが使えるのか？ (補足)

文字列はプリミティブ型ですが、`.toUpperCase()`などのメソッドを使えます。これは、メソッドを呼び出す瞬間だけ、JavaScriptが内部的にそのプリミティブ値を**一時的なオブジェクト**に変換（ラッパーオブジェクト化）し、メソッドの実行が終わると**すぐに破棄**しているためです。

### 2\. オブジェクト型（例: `Date`）

オブジェクト型には、`Date`、`Array`、`Object`、そして自作する`class`のインスタンスなどが含まれます。

| 項目 | `Date` オブジェクト |
| :--- | :--- |
| **データ** | **複雑な構造**と**複数の内部データ**を持つ。 |
| **メモリ** | 値そのものではなく、データが格納されている**場所（参照）** が格納される。 |
| **生成方法** | **コンストラクタ（`new`）** を呼び出して生成する。 |

#### `new`が必要な理由

`Date`オブジェクトは、以下の**複雑な初期設定**を伴うため、専用の工場である**コンストラクタ（`Date()`）** を通して生成する必要があります。

1.  **新しい実体の作成:** `new`演算子が新しい空のオブジェクト（インスタンス）を準備します。
2.  **初期化処理の実行:** `Date()`コンストラクタが実行され、その瞬間の「年」「月」「日」「時」「分」「秒」といった複数のデータを計算し、新しく作ったオブジェクトに設定（初期化）します。
3.  **実体の返却:** 初期化が完了したオブジェクトが変数に格納されます。

-----

## 🔑 まとめ

| 種類 | `Date`（オブジェクト型） | 文字列（プリミティブ型） |
| :--- | :--- | :--- |
| **生成** | `new Date()` | `let str = '...'` |
| **理由** | **複雑な内部状態**を持ち、**初期化処理**（コンストラクタ）が不可欠だから。 | **単純な値**であり、初期化処理が不要で、シンプルに扱えるから。 |

この違いが、JavaScriptにおけるメモリ管理やコードの振る舞いの基本となっています。

-----

## 🔍 値渡し（プリミティブ型）と参照渡し（オブジェクト型）

この2つの型の最も大きな違いは、「**値をコピーして渡すのか**」「**データの場所を指し示す情報（参照）を渡すのか**」という点にあります。

### 1\. プリミティブ型の場合：値渡し (Pass by Value)

プリミティブ型（文字列、数値など）の変数を別の変数に代入するときは、**値そのものがコピーされます**。

#### 💻 コード例

```javascript
let strA = 'Hello'; // ① strAに 'Hello' という値が入る
let strB = strA;   // ② strBに 'Hello' の「コピー」が入る

strB = 'World';    // ③ strBの値を変更

console.log(strA); // 結果: 'Hello'
console.log(strB); // 結果: 'World'
```

#### 💡 解説

1.  `strB = strA` のとき、`strA`が持っている値 `'Hello'` がメモリ上の**別の場所**にコピーされます。
2.  そのため、その後に`strB`だけを変更しても、`strA`の値には**全く影響がありません**。
3.  これは、2つの変数が**完全に独立した値**を持っているからです。

-----

### 2\. オブジェクト型の場合：参照渡し (Pass by Reference)

オブジェクト型（`Date`、`Array`、`Object`、`class`インスタンスなど）の変数を別の変数に代入するときは、オブジェクトのデータそのものではなく、データが格納されている**メモリ上の「場所」（参照）がコピーされます**。

#### 💻 コード例

```javascript
// 配列（オブジェクト型）を例にします
let arrA = [10, 20]; // ① arrAは、配列データがある「場所A」を指し示す
let arrB = arrA;     // ② arrBに「場所A」という情報（参照）がコピーされる

arrB.push(30);       // ③ arrBを使って、場所Aにある配列に要素を追加

console.log(arrA); // 結果: [10, 20, 30]
console.log(arrB); // 結果: [10, 20, 30]
```

#### 💡 解説

1.  `arrB = arrA` のとき、`arrA`と`arrB`は**同じ一つの配列データ（場所A）** を指し示しています。
2.  そのため、`arrB`を使ってデータを変更すると、**arrAから見ても**同じデータが変更されていることになります。
3.  これは、2つの変数が**同じ実体**を共有しているからです。

-----

## 🔑 まとめ

この「値渡し」と「参照渡し」の挙動は、JavaScriptで意図しないバグを防ぐために非常に重要です。

| 特徴 | プリミティブ型 (値渡し) | オブジェクト型 (参照渡し) |
| :--- | :--- | :--- |
| **代入時** | 値が**コピー**される。 | データの場所（参照）がコピーされる。 |
| 変更の影響 | 片方を変更しても、もう片方に影響しない。 | 片方を変更すると、もう片方にも**影響する**。 |

この「参照渡し」の概念は、`forEach`などを使って配列の要素を処理するとき（要素がオブジェクトの場合）にも関わってくる、重要な知識です。
