# 🔎 JavaScriptの変数のスコープ（Scope）

JavaScriptにおける**スコープ**とは、**変数がどこからアクセス（利用）できるか**を決める「**変数の見える範囲**」のことです。変数を宣言する方法（`var`, `let`, `const`）によって、この見える範囲が大きく異なります。

-----

## 1\. グローバルスコープ (Global Scope) 🌎

**グローバルスコープ**で宣言された変数は、コードの**どこからでも**アクセスできます。

  * **定義:** 関数の外側やブロック（`{}`）の外側で宣言された変数です。
  * **特徴:** プログラム全体で共有されるため、どこかで値を変更すると、それが全体に影響します。安易な利用は、コードの予期せぬ動作（バグ）につながりやすいため、**非推奨**とされることが多いです。

<!-- end list -->

```javascript
// グローバルスコープ
const globalMessage = "世界中に見えるメッセージ";

function showGlobal() {
  console.log(globalMessage); // どこからでもアクセスできる
}

showGlobal();
```

-----

## 2\. 関数スコープ (Function Scope) ⚙️

**関数スコープ**は、主に古いバージョンのJavaScriptで使われていた `var` キーワードの変数が持つスコープです。

  * **定義:** 変数が宣言された**関数の中**でのみアクセス可能です。
  * **特徴:** 関数を抜けると、変数は消滅し、外側からはアクセスできません。

<!-- end list -->

```javascript
function myFunction() {
  // 関数スコープ
  var functionVar = "私は関数の中でのみ生きる";
  console.log(functionVar); // 関数内OK
}

myFunction();

// console.log(functionVar); // エラー: functionVar は定義されていません
```

-----

## 3\. ブロックスコープ (Block Scope) 🧱

**ブロックスコープ**は、`let` や `const` キーワードで宣言された変数が持つスコープです。最新のJavaScript（ES6以降）では、このブロックスコープが主流です。

  * **定義:** 変数が宣言された**ブロック `{}`（if文、for文、while文などの波括弧）の中**でのみアクセス可能です。
  * **特徴:** 変数の有効範囲が狭くなり、意図しない場所での変数の上書きを防げるため、より安全で管理しやすいコードになります。

<!-- end list -->

```javascript
if (true) {
  // ブロックスコープ
  let blockLet = "私はブロックの中だけ";
  const blockConst = 100;
  console.log(blockLet); // ブロック内OK
}

// console.log(blockLet); // エラー: blockLet は定義されていません
// console.log(blockConst); // エラー
```

-----

## 🔑 宣言キーワードによる違いのまとめ

| キーワード | スコープの種類 | 特徴 | 推奨度 |
| :---: | :---: | :--- | :---: |
| `var` | **関数スコープ** | 古い。意図せず関数の外側からアクセスできてしまうなど、混乱を招きやすい。 | 低い |
| `let` | **ブロックスコープ** | 変数。再代入（値の変更）が可能。 | 高い |
| `const` | **ブロックスコープ** | 定数。再代入（値の変更）は不可。 | **最高** |

> 💡 **ポイント:** 現代のJavaScriptでは、デフォルトで **`const` ** を使い、値を変える必要がある場合にのみ ** `let`** を使うのがベストプラクティスとされています。`var` の使用は避けることが推奨されます。

-----

## 🧊 `const` の不変性（Immutability）の理解

。`const` が防ぐのは「**再代入**」だけであり、「**中身の変更**」は防がない、というこの違いは、初心者にとって最も混乱しやすいポイントの一つです。

これを理解するために、変数を「**名札**」、データ（オブジェクトや配列）を「**箱**」に例えて説明します。

-----

### 1\. プリミティブ値の場合 (`const` = 完全に固定)

数値や文字列などのプリミティブな値は、名札が直接その値（情報）を指しています。

```javascript
const favoriteNumber = 10;
// favoriteNumber (名札)  ->  10 (値)
```

この場合、`const` は以下の操作を防ぎます。

| 操作 | 結果 | 理由 |
| :--- | :--- | :--- |
| `favoriteNumber = 20;` | ❌ **エラー** | `const` のルールにより、名札を別の新しい値に**付け替える（再代入する）** ことを禁止しているからです。 |

プリミティブ値は箱を持たないため、名札が固定されれば、値は完全に不変になります。

-----

### 2\. オブジェクトや配列の場合 (`const` = 名札の固定)

オブジェクトや配列は「**参照型**」データと呼ばれます。この場合、名札が指しているのは、データが格納されている**メモリ上の「箱」（アドレス）** です。

```javascript
const person = { name: "Alice", age: 25 };
// person (名札)  ->  [メモリのアドレス]  ->  { name: "Alice", age: 25 } (箱の中身)
```

このとき、`const` は以下の操作を許可し、禁止します。

#### ❌ 禁止される操作：名札の付け替え（再代入）

`const` が防ぐのは、`person` という名札を**別の新しい箱に付け替える**操作です。

```javascript
// 新しい別のオブジェクト
const newPerson = { name: "Bob", age: 30 }; 

// 再代入を試みる
// person = newPerson; 
// 👆 ❌ TypeError! (名札を新しい箱に付け替えることはできません)
```

#### ✅ 許可される操作：箱の中身の変更

`const` は、**名札が指している箱の「中身」（プロパティ）をいじる**操作は制限しません。

```javascript
// 箱の中身のプロパティを更新する
person.age = 26; // 👈 ✅ OK!

// 箱の中に新しいプロパティを追加する
person.city = "Tokyo"; // 👈 ✅ OK!

console.log(person); 
// 出力: { name: "Alice", age: 26, city: "Tokyo" }
```

名札 (`person`) は常に同じ箱を指し続けているため、`const` のルールは破られていない、とJavaScriptは判断します。

### まとめ

| キーワード | 許可される操作 | 禁止される操作 |
| :---: | :--- | :--- |
| `const` | オブジェクトや配列の**中身の変更** | 変数への**再代入（名札の付け替え）** |
| `let` | 中身の変更も、変数への再代入も可能 | なし |

この動作は、`const` は「値の不変性」ではなく「**参照の不変性**」を保証している、と理解すると、より正確です。
