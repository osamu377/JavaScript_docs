正規表現せいきひょうげん

プログラミングを勉強べんきょうしていると必かならず出会であう、魔法まほうの言葉ことばのような記号きごうの羅列られつ。それが「正規表現せいきひょうげん」です。英語えいごで “Regular Expression” と言いいます。

JavaScriptでは、RegExp（レグエクスプ） オブジェクトを使つかいます。

RegExpは 「魔法まほうの虫むしめがね」 です。たくさんの文字もじの中なかから、自分じぶんの探さがしたい「パターン」だけをピカッと光ひからせて見みつけることができます。

I. 「正規表現せいきひょうげん」ってなに？

普通ふつうの検索けんさく（indexOf など）は、「特定とくていの言葉ことば」を探さがします。
RegExpは、「言葉ことばのパターン（ルール）」 を探さがします。

  • 普通ふつうの検索けんさく： 「『田中たなか』さんを探さがして」
  • RegExp： 「『数字すうじが3つ、ハイフン、数字すうじが4つ』の形かたち（電話番号でんわばんごう）を探さがして」

このように、あやふやなルールで検索けんさくできるのがすごいところです。

II. RegExpオブジェクトの作つくり方かた

2つの書かき方かたがありますが、よく使つかわれるのは / /（スラッシュ） で囲かこむ方法ほうほうです。

// 1. スラッシュで囲む（リテラル） ★おすすめ
const pattern1 = /abc/;

// 2. new を使う
const pattern2 = new RegExp("abc");

III. よく使つかう「魔法まほうの記号きごう」（１）

正規表現せいきひょうげん（RegExp）の メタ文字もじ は、文字もじの 「種類しゅるい」 や 「数かず」 を指定していする特別とくべつなルールです。
「トランプのジョーカー」 や 「算数さんすうのルール」 に例たとえて説明せつめいすると、パズルのように楽たのしく理解りかいできます。

よく使つかわれる7つの記号きごう(メタ文字もじ) を、やさしく解説かいせつします！

1. . （ドット）

→「なんでもいい一文字もじ」

  • イメージ： トランプの「ジョーカー」や、クイズの「穴埋あなう（あなう）め」です。
  • ルール： 数字すうじでも、漢字かんじでも、アルファベットでも、**「とにかく1文字もじ」**あればOK。

例れい： /あ.い/

  • 「あいい」 … OK
  • 「ああい」 … OK
  • 「あ1い」 … OK
  • 「あい」 … NG（文字もじが足たりない）

2. * （アスタリスク）

→「0回以上かいいじょうのくり返かえし」

  • イメージ： おかわり自由じゆう。「なくてもいいし、無限むげん（むげん）にあってもいい」。
  • ルール： 直前ちょくぜん（ちょくぜん）の文字もじが「0個こ、1個こ、2個こ……」と、いくつ続つづいていてもOK。

例れい： /あ*い/

  • 「い」 … OK（「あ」が0個こでもいい）
  • 「あい」 … OK
  • 「あああい」 … OK

3. + （プラス）

→「1回以上かいいじょうのくり返かえし」

  • イメージ： 最低さいてい（さいてい）でも1つは必要ひつよう。「1個以上こいじょうなら、いくつでもいい」。
  • ルール： 直前ちょくぜんの文字もじが「1個こ、2個こ、3個こ……」と続つづいていればOK。

例れい： /あ+い/

  • 「い」 … NG（「あ」が最低さいてい1つは必要ひつよう！）
  • 「あい」 … OK
  • 「あああい」 … OK

4. ? （クエスチョン）

→「0回かいか 1回かいだけ」

  • イメージ： 「あってもなくてもいい（最大さいだい1つまで）」。
  • ルール： 直前ちょくぜんの文字もじが「ない」か「1個こだけある」状態じょうたい。

例れい： /あ?い/

  • 「い」 … OK
  • 「あい」 … OK
  • 「ああい」 … NG（2個以上こいじょうはダメ）

5. ^（キャレット）

→「行ぎょうがここから始はじまる」

  • イメージ： マラソンの「スタートライン」です。
  • ルール： その文字もじで文章ぶんしょうが始はじまっていることをチェックします。

例れい： /^おはよう/

  • 「おはようございます」 … OK
  • 「みんな、おはよう」 … NG（「みんな」から始はじまっているから）

6. $ （ドル）

→「行ぎょうの最後さいごがこれでおわる」

  • イメージ： マラソンの「ゴールテープ」です。
  • ルール： その文字もじで文章ぶんしょうが終おわっていることをチェックします。

例れい： /です$/

  • 「田中たなかです」 … OK
  • 「田中たなかですよ」 … NG（「よ」で終おわっているから）

7. | （パイプ・縦線たてせん）

→「または（OR）」

  • イメージ： レストランのメニュー。「A または B どちらか選えらんで」というルール。
  • ルール： 左側ひだりがわか右側みぎがわ、どちらかの文字もじがあればOK。

例れい： /りんご|みかん/

  • 「りんご」 … OK
  • 「みかん」 … OK
  • 「バナナ」 … NG

覚おぼえ方かたのまとめテーブル

記号きごう意味いみ覚おぼえ方かたのヒント
.なんでも1文字もじ何なにが入はいるかワクワクする「穴あな」
*0個以上こいじょうおかわり自由じゆう（なくてもいい）
+1個以上こいじょう必かならず1つは持もってきて！
?0か1個こオプション（あってもなくてもいい）
^始はじまり文ぶんの最初さいしょにあるスタートライン
$終おわり文ぶんの最後さいごにあるゴールテープ
|またはAかB、どちらか好すきな方ほう！

いかがでしょうか？ 記号きごうの「パワー」を知しると、短みじかいコードで複雑ふくざつなチェックができるようになります。

IV. よく使つかう「魔法まほうの記号きごう」（２）

正規表現せいきひょうげん（RegExp）のメタ文字もじ、さらに便利べんりなものを紹介しょうかいします！ 今回こんかいは、文字もじを 「グループ化か」 したり、「回数かいすうを正確せいかくに指定してい」 したりする、少すこし高度こうどなルールです。

「チーム作づくり」 や 「回数かいすうの予約よやく」 に例たとえて説明せつめいます。

1. () （かっこ）

→「チーム（グループ）を作つくる」

  • イメージ： 複数ふくすうの文字もじをひとつにまとめて「1つのチーム」として扱あつかいます。
  • ルール： チームに対たいして、さっき勉強べんきょうした * や + を使つかうことができます。

例れい： /(abc)+/

  • 「abc」 … OK
  • 「abcabcabc」 … OK（「abc」というチームが繰くり返かえされている）
  • 「abcc」 … NG（チーム全員ぜんいんで繰くり返かえさないとダメ）

2. [] （角かくかっこ）

→「この中なかのどれか1文字もじ」

  • イメージ： 「この中なか（リスト）にある文字もじなら、誰だれでもいいよ」という メンバー名簿めいぼ です。
  • ルール： カッコの中なかに入はいっている文字もじのどれか1つに合あえばOK。

例れい： /[ABC]くん/

  • 「Aくん」 … OK
  • 「Bくん」 … OK
  • 「Cくん」 … OK
  • 「Dくん」 … NG（名簿めいぼに名前なまえがない）

このように[]で囲かこまれて『この中なかのどれか1つに合あえばOK』という文字もじのグループを 文字もじクラス といいます。

文字もじクラス にはいくつかのバリエーションがあります。

  • 文字もじクラスの先頭せんとうに^をつけると、文字もじクラスの否定ひていを表あらわします 。

例れい： /[^ABC]くん/

  • 「Aくん」 … NG
  • 「Bくん」 … NG
  • 「Cくん」 … NG
  • 「Dくん」 … OK（名簿めいぼに名前なまえがないものがOK）
  • 数字すうじやアルファベットが連続れんぞくしているとき、最初さいしょの文字もじと最後さいごの文字もじを-でつなげて、短みじかく書かくことができます。

例れい： /[A-C]くん/

  • 「Aくん」 … OK
  • 「Bくん」 … OK
  • 「Cくん」 … OK
  • 「Dくん」 … NG（AからCのあいだにない文字もじ）

3. {n} {n,} {n, m} （波なみかっこ）

→「回数かいすうを数字すうじで指定していする」

これらは + や * よりも、もっと細こまかく 「何回なんかいか」 を予約よやくする記号きごうです。

{n} ：ぴったり n回かい

  • 例れい： /\d{3}/ （数字すうじがぴったり3つ）
  • 「123」はOK、「12」はNG。

{n,} ：n回以上かいいじょう（いくらでも）

  • 例れい： /\d{3,}/ （数字すうじが3つ以上いじょう）
  • 「123」も「12345」もOK。

{n, m} ：n回かいから m回かいのあいだ

  • 例れい： /\d{3,5}/ （数字すうじが3つ、4つ、または5つ）
  • 「1234」はOK、「123456」はNG。

4. \ （バックスラッシュ / 円えんマーク）

→「魔法まほうを消けして、普通ふつうの文字もじに戻もどす」

  • イメージ： 「エスケープ（逃にがす）」 といいます。特別とくべつな力ちからを持もっているメタ文字もじから、魔法まほうを取とり上あげます。
  • ルール： メタ文字もじの前まえに書かくと、ただの「記号きごう」として探さがせるようになります。

例れい： 普通ふつうのドット（.）を探さがしたいとき

  • . だけだと「なんでも1文字もじ」という魔法まほうが発動はつどうします。
  • /\./ と書かくと、文章ぶんしょうの中なかにある**「点てん（ドット）」**そのものを探さがせます。

まとめテーブル（留学生向りゅうがくせいむけ）

記号きごう意味いみ覚おぼえ方かたのヒント
( )グループ化か「みんなで1つのチームだよ！」
[ ]どれか1つ「このリストの中なかの誰だれか1人り！」
{n}ぴったり n回かい「回数かいすうを予約よやく（よやく）する」
{n, m}n回かい〜m回かい「最小さいしょうと最大さいだいを決きめる」
\エスケープ「魔法まほうをキャンセル！」

いかがでしょうか？これで正規表現せいきひょうげんの主要しゅようなパーツが揃そろいました。

留学生りゅうがくせいへのアドバイス

RegExpは、最初さいしょは難むずかしくて「暗号あんごう」に見みえます。でも、全部ぜんぶ覚おぼえる必要ひつようはありません！

「RegExpは 『文字もじの形かたちをチェックするルールブック』 だよ。
郵便番号ゆうびんばんごう、メールアドレス、パスワードの強つよさ（英数字えいすうじが入はいっているか）を調しらべるときに、世界中せかいじゅうのプログラマーが使つかっているんだ。
難むずかしいパターンは、インターネットで『RegExp 郵便番号ゆうびんばんごう』のように検索けんさくしてコピーすれば大丈夫だいじょうぶだよ！」

Important

スラッシュ / / の後あとろにつけるオプション（フラグ）

  • /abc/i ：大文字おおもじと小文字こもじを区別くべつしない（ignore）。
  • /abc/g ：全部ぜんぶ探さがす（global）。

この2つを知しると、さらに便利べんりに使つかってもらえます。

いかがでしょうか？「完璧かんぺきなパターンを自分じぶんで書かく」ことよりも、「ルールで検索けんさくできる便利べんりな道具どうぐがある」ことを知しることが第一歩だいいっぽです！

V. 実際じっさいに使つかってみよう

よくある「メールアドレスの入力にゅうりょくチェック」のようなイメージです。

const myPattern = /apple/; // 「apple」という文字があるか？
const text = "I have an apple.";

// testメソッド：パターンに合っているかチェック（true / false）
if (myPattern.test(text)) {
  console.log("見つかりました！");
}

1. Stringオブジェクトのmatch()メソッドと連携れんけい

上うえの例れいでは、RegExpオブジェクトのtest()メソッドを使つかって、そのパターンが含ふくまれているかどうかをチェックしました。

しかし、JavaScriptで文字列もじれつの中なかから特定とくていの文字もじを探さがし出だすときに、一番いちばんよく使つかわれるのは、「RegExpオブジェクト（パターン）」と「Stringメソッドの match()」の連携れんけい という、強力きょうりょくな組くみ合あわせです。

RegExpの test() や exec() はパターンが主語しゅごでしたが、match() は文字列もじれつが主語しゅごになります。

  • 書かき方かたの形かたち： 文字列もじれつ.match(パターン)

例たとえ： 「この文章ぶんしょうのなかで（文字列もじれつ）、このルールに合あうものを（パターン）、集あつめてちょうだい！（match）」

例れい

const myRegExp = new RegExp("app.*"); // 「app.*」というパターンがあるか？
const text = "I have an apple.";

mat = text.match(myRegExp);
if (mat !== null)
  console.log("見つかりました！");
  console.log(mat); // ['apple.', index: 10, input: 'I have an apple.', groups: undefined]

match()メソッドの戻もどり値ちは配列はいれつで、上うえの場合ばあい

  • マッチした最初さいしょの文字列もじれつ (apple)
  • マッチした文字もじの位置いち (10)
  • 調しらべた対象たいしょうの文字列もじれつ ('I have an apple.')

です（groupsについての解説かいせつは省略しょうりゃく）。

2. 正規表現せいきひょうげんの g フラグによる動うごきの変化へんか

match() の本当ほんとうの面白おもしろさは、正規表現せいきひょうげんの後うしろにつける**g（グローバルフラグ：全部探ぜんぶさがすという意味いみ）** があるかないかで、返かえってくる結果けっかの形かたち（データ型がた）がガラリと変かわることです。

g フラグをとき： 合あうものを全部集ぜんぶあつめてリストに

文字列もじれつの中なかを上うえから下したまで全部調ぜんぶしらべて、パターンに合あう言葉ことばを「ただのきれいな配列はいれつ（リスト）」にして全部返ぜんぶかえしてくれます。詳くわしい情報じょうほうは入はいりません。

const text = "私の学校には、Aクラス、Bクラス、Cクラスがあります。";

const myRegExpG = new RegExp("クラス", "g"); // うしろに g をつけました！

const resultG = text.match(myRegExpG);
console.log(resultG); // ["クラス", "クラス", "クラス"] （3つぜんぶつかまえた！）
console.log(resultG.length); // 3 （いくつ見つかったかもすぐわかります）

Note

もし文字列もじれつの中なかにパターンに合あう言葉ことばが1つもなかった場合ばあい、match() はどちらの場合ばあいでも**null（空からっぽ）** を返かえします。

3. i フラグの i は何なにの略りゃく？

この i は、英語えいごの IgnoreCase（イグノア・ケース：大文字小文字おおもじこもじを無視むしする） という言葉ことばの頭文字かしらもじです。

通常つうじょう、JavaScriptの正規表現せいきひょうげんは大文字おおもじと小文字こもじを「完全かんぜんに別べつの文字もじ」として区別くべつします。しかし、i フラグをつけると、それらを 同おなじ文字もじ として扱あつかってくれるようになります。

コードで見みる違ちがい（フラグがある時とき・ない時とき）

自分じぶんのパソコンのブランド（Apple）について書かいた文章ぶんしょうから文字もじを探さがしてみましょう。

const text = "My computer is an apple MacBook."; // 小文字の apple

// 1. i フラグを【つけない】とき（きびしく さがす）
const regExp1 = new RegExp("Apple"); // 大文字の A
console.log(text.match(regExp1) !== null); // false （大文字と小文字がちがうので、見つからない！）

// 2. i フラグを【つける】とき（やさしく さがす）
const regExp2 = new RegExp("Apple", "i"); // うしろに i をつけました！
console.log(text.match(regExp2) !== null); // true  （大文字小文字をむしするので、見つかった！）

このように、パターンのスラッシュの後あとろに /パターン/i と書かくだけで、Apple も apple も APPLE も、ぜんぶ一緒いっしょに見みつけてくれるようになります。

前まえに習ならった g フラグと一緒いっしょに使つかえる？

はい、一緒いっしょに使つかえます！ 順番じゅんばんは ig でも gi でもどちらでも大丈夫だいじょうぶです。
これらを組くみ合あわせると、「大文字小文字おおもじこもじを気きにせず（ i ）、文章全体ぶんしょうぜんたいからすべて集あつめる（ g ）」 という強力きょうりょくな捜査そうさができます。

const text = "JavaScript is great. I love javascript!";

// 大文字小文字を気にせず（i）、ぜんぶ集める（g）
const myRegExp = new RegExp("javascript", "ig"); 

const result = text.match(myRegExp);
console.log(result); // ["JavaScript", "javascript"] （両方ともしっかり捕まえた！）
